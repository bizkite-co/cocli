# Similar products a photographer would compare (not a git-annex census)

Research date: 2026-10-24. Comparison target (not researched as a product): open-source software, customer-paid object storage (S3 Glacier, B2, Wasabi, R2, IDrive e2, or similar), a seller-installed on-site NUC-class hub, originals pushed off the hub, source removed only after two copies exist, content-addressed dedup with the original folder path kept in metadata, plus an on-hub web gallery and AI (captions, OCR, embeddings, faces, audio/video transcripts), with a phone web catalog already and an Android app not yet shipping.

None of the official pages opened below (Immich, PhotoPrism, Ente, LibrePhotos, Nextcloud, PiGallery2, Photoview, Arq, Mylio, Synology C2, TrueNAS apps) mentioned git-annex. That is not a full-site audit.

## Self-hosted photo and video servers with web and mobile

### Takeaway

The products a photographer would actually open next to this offer are Immich and, second, PhotoPrism or Ente. Immich is the only one in this set with native phone backup, on-server faces, CLIP search, and library-wide OCR in current official docs, but its library is a local filesystem (or a mount), not customer Glacier, and “free up space” deletes the phone copy after one server upload. PhotoPrism indexes an existing folder in place and can add captions, but it has no first-party phone agent and no object-storage library. Ente is the one that stores originals in S3-compatible buckets, including a documented “cold” replica bucket, but the hosted product bills Ente for storage and AI runs on the device because the server only sees ciphertext. Nobody in this set documents “delete the source only after both a hub copy and a verified cold-object copy exist,” and nobody documents content-addressed blob storage that keeps the folder path only as metadata.

### Cited Findings

**Immich (closest live-app substitute)**

- License reported as AGPL-3.0, including facial recognition and smart search, with an optional FUTO “product key” that does not unlock extra features. Reviewers say they checked the GitHub LICENSE file; this pass did not open that file. — [SelfHostLab, 2026-07-14](https://selfhostlab.io/apps/immich/); [Contabo, 2026-07-27](https://contabo.com/blog/best-self-hosted-photo-apps/)
- Storage in the official install docs is a Unix filesystem bind mount (`UPLOAD_LOCATION`, optional separate thumb and encoded-video paths). Postgres “should ideally use local SSD storage, and never a network share.” There is no S3, B2, R2, or Glacier library backend in those pages. — [Files Custom Locations](https://docs.immich.app/guides/custom-locations/); [Requirements](https://docs.immich.app/install/requirements)
- External libraries are directories mounted into the container and scanned. The guide assumes files “are stored in a directory on the same machine.” Read-only is the default; write access is only so Immich can delete or write XMP. — [External library guide](https://github.com/immich-app/immich/blob/main/docs/docs/guides/external-library.md)
- A community compose file mounts S3/WebDAV via rclone and then adds that path as an external library (3 GitHub stars). That is a FUSE mount, not an Immich storage driver. — [toby1991/immich-s3](https://github.com/toby1991/immich-s3)
- Backblaze Labs published an “Immich B2 Backend” on 2026-10-19 that stores originals, thumbnails, and CLIP embeddings on B2. The page labels it “unsupported,” “no SLA,” and explicitly out of scope for face recognition and video transcoding. It is not the Immich server. — [Backblaze Labs](https://www.backblaze.com/labs/projects/immich-object-storage-backend/)
- Phone: iOS, Android (Play, GitHub APK, Obtainium), and web. Backup uploads selected albums in the foreground and in the background, Wi-Fi only unless changed. On first selection it checksums file content and skips bytes already on the server. — [Mobile backup](https://docs.immich.app/features/mobile-backup); [Post-install](https://docs.immich.app/install/post-install)
- “Free Up Space” (shipped around v2.5, January 2026; documented on the current mobile-app page) removes device files only after Immich considers them backed up to the server and not in Immich trash. The user sets a cutoff date, can keep favorites and chosen albums, reviews the list, and deletion goes to the phone’s trash. The check is one server copy, not a second off-site copy. Database dumps “do not contain photos or videos”; filesystem backup of `UPLOAD_LOCATION` is the operator’s job. — [Mobile app: Free Up Space](https://docs.immich.app/features/mobile-app); [v2.5.0 discussion](https://github.com/immich-app/immich/discussions/25577); [Backup and restore](https://github.com/immich-app/immich/blob/main/docs/docs/administration/backup-and-restore.md)
- Dedup is not content-addressed storage. Upload skip uses a content checksum. A separate duplicates utility groups visually similar assets with a machine-learning distance and lets the user trash or stack them; larger files and richer EXIF are preselected. Storage templates place files at paths like `Year/Year-Month-Day/Filename.Extension`. — [Duplicates utility](https://docs.immich.app/features/duplicates-utility); [Storage template](https://docs.immich.app/administration/storage-template)
- AI on the server: CLIP smart search (default model `ViT-B-32__openai`; FAQ says this does not produce readable captions or tags), facial recognition (default `buffalo_l`), and OCR search (“Text in images”). The published config defaults OCR to enabled with `PP-OCRv5_mobile`. A secondary report (2026-10-11) says Immich 3.3 added PP-OCRv6 tiny/small/medium; the config example still names v5, so v6 should be treated as an added model family, not a confirmed new default. Face detection on video uses the thumbnail only. No speech or video transcription appears in the searching, FAQ, or architecture pages opened here. — [Searching](https://docs.immich.app/features/searching/); [FAQ](https://docs.immich.app/FAQ); [Config file](https://docs.immich.app/install/config-file); [abit.ee on 3.3](https://abit.ee/en/soft/video-editors/immich-33-immich-photo-storage-self-hosted-open-source-ocr-pp-ocrv6-en)
- v3.0.0 is dated 2026-07-01 by a host roundup (HLS, mobile non-destructive edit). Star counts in July 2026 roundups are about 102k–109k. Those counts are secondary. — [Contabo](https://contabo.com/blog/best-self-hosted-photo-apps/); [SelfHostLab](https://selfhostlab.io/apps/immich/)

**PhotoPrism**

- Community Edition is self-hosted, storage “unlimited,” price FREE, and the editions table marks “AGPL License” on that row only. Paid rows are Essentials €2.00/mo, Plus from €6.00/mo, and managed PikaPods from $6.50/mo. Team licenses: Starter €79.00/mo (up to 10 users), Business from €219.00/mo, Enterprise from €1499.00/mo. Remote setup is listed at €499.00; onboarding and other services at €179.00/hour. — [Editions](https://www.photoprism.app/editions); [Team editions](https://www.photoprism.app/kb/teams/)
- Aggregators disagree with that page and with each other: one table calls Essentials “€2/yr” while quoting “€ 2.00 / mo; billed annually,” and another says paid plans “start at €1,499/mo.” Use the editions page, and treat the billing period as unsettled until checkout. — [HowPremium](https://howpremium.com/plans/photoprism/pricing/); [TechYorker](https://techyorker.com/products/photoprism/pricing/)
- Originals live in a folder (`PHOTOPRISM_ORIGINALS_PATH`). Indexing leaves names and folders unchanged. Import copies or moves into originals, skips duplicates, and renames by content and metadata (year/month). PhotoPrism “will generally not move, rename, or otherwise modify” originals unless asked. There is no S3/Glacier library in the originals, folders, or WebDAV docs opened here. — [Indexing originals](https://docs.photoprism.app/user-guide/library/originals/); [Library intro](https://docs.photoprism.app/user-guide/library/); [Directory overview](https://docs.photoprism.app/user-guide/backups/folders/)
- Duplicate detection compares SHA1 and size and skips duplicates so they appear once. The web UI for browsing and deleting duplicates is “planned for a future release.” Import “Move” deletes the source file after the copy into originals. That is one local copy, not a verified cloud replica. — [Duplicate detection](https://docs.photoprism.app/user-guide/library/duplicates/)
- Mobile row on every edition, including Community, is “PWA & PhotoSync,” not a first-party iOS/Android backup app. WebDAV can mount originals and import. — [Editions](https://www.photoprism.app/editions); [WebDAV](https://docs.photoprism.app/user-guide/sync/webdav/)
- Faces are built in (YuNet detection, SFace embeddings on ONNX; older libraries stay on FaceNet until `photoprism faces migrate`). Labels default to a built-in ONNX classifier. Captions and richer labels are optional via self-hosted Ollama or the OpenAI API, configured in `vision.yml`. PhotoPrism’s own Ollama notes say Qwen3-VL has “32-language OCR” inside that vision model; that is model capability, not a documented library-wide OCR search index. No audio/video transcript feature was on the AI pages opened. — [User-guide AI](https://docs.photoprism.app/user-guide/ai/); [Face recognition](https://docs.photoprism.app/user-guide/ai/face-recognition/); [Ollama setup](https://docs.photoprism.app/user-guide/ai/using-ollama/); [Ollama package README, updated 2026-10-08](https://github.com/photoprism/photoprism/blob/develop/internal/ai/vision/ollama/README.md)

**Ente Photos**

- Hosted service: end-to-end encrypted; clients upload ciphertext; Ente says it cannot read photos. Hosted plans store replicas on Ente’s providers (TechCrunch, April 2025: three locations). The customer does not point hosted Ente at their own Glacier account. — [TechCrunch, 2025-04-01](https://techcrunch.com/2025/04/01/ente-wants-to-take-on-google-photos-with-its-privacy-first-photo-storage-service/); [Ente storage FAQ](https://ente.com/help/photos/faq/storage-and-plans)
- Official FAQ: free plan is 10 GB and is replaced, not stacked, on upgrade; paid tiers run from 50 GB to multiple TB; family sharing up to 5 people; one global price. Dollar amounts below are from pages that say they copied ente.com on 2026-10-15, not from an ente.com pricing HTML fetch in this pass: Free 10 GB; Starter $2.49/mo or $29.88/yr (50 GB); Popular $4.99/mo or $59.88/yr (200 GB); Pro $9.99/mo or $119.88/yr (1000 GB); Pro+ $19.99/mo or $239.88/yr (2000 GB). TechCrunch’s April 2025 “from $9.99/mo for 1 TB” is an older, higher entry tier. — [Storage and plans FAQ](https://ente.com/help/photos/faq/storage-and-plans); [Position Is Everything](https://www.positioniseverything.net/tools/ente-photos/pricing/); [TechCrunch](https://techcrunch.com/2025/04/01/ente-wants-to-take-on-google-photos-with-its-privacy-first-photo-storage-service/)
- Self-host: server (“Museum”) is the same code as production, AGPL per secondary roundups. Quickstart is Docker Compose with Postgres, MinIO, and a web UI. Files are S3 objects. Default bucket keys in `museum.yaml` are named `b2-eu-cen` (primary), `wasabi-eu-central-2-v3` (secondary), and `scw-eu-fr-v3` (documented as cold storage). Replication is a flag. External S3 is supported by setting `s3.are_local_buckets` to false. The docs do not say those buckets can be Glacier or Deep Archive, and they do not describe deleting a camera-card or phone original after two copies. — [Object storage admin](https://ente.io/help/self-hosting/administration/object-storage); [Config](https://ente.com/help/self-hosting/installation/config); [Self-host index](https://github.com/ente-io/ente/blob/main/docs/docs/self-hosting/index.md); [Contabo](https://contabo.com/blog/immich-vs-photoprism-vs-ente/)
- Apps: Android, iOS, desktop, and web. Machine learning is on-device and off by default: face clustering and CLIP “magic search.” It is not available on web.ente.io. Detect Text (OCR) is an on-demand viewer action on iOS and Android photos and Live Photos, explicitly not a searchable index and not for videos. No transcript feature was on the ML pages. Because the server holds ciphertext, server-side captions or transcripts are incompatible with the hosted design unless they also run on the client. — [Machine learning](https://ente.io/help/photos/features/search-and-discovery/machine-learning); [Magic search](https://ente.io/help/photos/features/search-and-discovery/magic-search); [Detect Text](https://ente.com/help/photos/features/utilities/detect-text); [Search and discovery](https://ente.io/help/photos/features/search-and-discovery/)

**LibrePhotos**

- MIT licensed. It scans folders the user already has, runs face detection (InsightFace) and clustering, places, tags, and generated captions, and states that nothing is sent to a third party. Docs homepage says Docker, Kubernetes, Unraid, or a standalone Windows build, and “Android app included.” — [LibrePhotos docs](https://docs.librephotos.com/); [GitHub README](https://github.com/LibrePhotos/librephotos)
- Mobile docs (page dated 2026-02-23) still call the official app a proof of concept, React Native, Android APK only, and say iOS is possible but nobody has shipped it. The monorepo README, with the org repo pushed 2026-10-24, describes `apps/mobile` as “Expo mobile app (Android and iOS), offline-first.” Those two primary pages conflict; do not treat a shipping iOS app as confirmed. — [Mobile guide](https://docs.librephotos.com/docs/user-guide/mobile/librephotos-mobile/); [GitHub](https://github.com/LibrePhotos/librephotos)
- No S3, Glacier, or “delete after verified cloud copy” language on the docs homepage or README. Storage is the folders it scans.

**Nextcloud Photos / Memories**

- Memories is a Nextcloud app: timeline from EXIF, albums, external sharing, metadata edit, and a phone-usable web UI. AI tagging is delegated to the Recognize and Face Recognition apps, not built into Memories. — [Memories on the Nextcloud app store](https://apps.nextcloud.com/apps/memories)
- Recognize (current manual is for Nextcloud 35) does on-prem faces, object and landmark tags, music-genre tags, and video action tags. The newer `recognize_backend` uses InsightFace `buffalo_l` for faces, ConvNeXt V2 for objects, an Audio Spectrogram Transformer for genres, and VideoMAE for actions. That is not image OCR and not speech-to-text. — [Recognize admin manual](https://docs.nextcloud.com/server/stable/admin_manual/ai/app_recognize.html)
- Files can live on Amazon S3 or any S3-compatible store as external storage or as primary object storage (MinIO and Ceph are named). The S3 pages document bucket, region, hostname, and an optional storage class. They do not discuss Glacier retrieval delays, so a live Memories library on Glacier is not an official configuration. — [Amazon S3 external storage](https://docs.nextcloud.com/server/latest/admin_manual/configuration_files/external_storage/amazons3.html); [Primary object storage](https://docs.nextcloud.com/server/stable/admin_manual/configuration_files/primary_storage.html)
- Phone access is the Nextcloud sync app plus the Memories web UI, not a Memories-branded store app. A July 2026 roundup marks mobile sync “partial” and AI search absent at the Memories layer, which matches the split above. — [Pluto Photos comparison, 2026-04-23](https://plutophotos.com/blog/best-self-hosted-photo-management-2026/)

A third-party summary says it reads Adobe XMP face regions; the official feature list excerpt does not claim it runs its own face detector, OCR, captions, or transcripts. - Photoview (homepage updated 2025-10-16) scans a filesystem, turns directories into albums, shows EXIF, maps, and transcodes video. The same page says the official iOS app is “no longer maintained or available on the AppStore.” GitHub lists the project as AGPL-3.0; the Android repo’s last update on the org page is 2022-07-13 and the iOS repo’s is 2023-03-02. No face, OCR, caption, or transcript features on the homepage. TrueNAS community app, added 2025-07-15. — [Photoview](https://photoview.github.io/); [GitHub org](https://github.com/orgs/photoview/repositories); [TrueNAS catalog](https://apps.truenas.com/catalog/)

**2025–2026 names that are actually discussed**

- Immich’s own 2026 releases (Free Up Space in 2.5; v3.0.0 on 2026-07-01; OCR model work reported for 3.3 on 2026-10-11) are the activity photographers are reacting to, not a new archive product. — sources above
- Pluto Photos (vendor post, 2026-04-23) is a desktop app with a built-in editor. The post tells readers who want a server to use Immich, PhotoPrism, or Nextcloud Memories instead. Different job. — [Pluto Photos](https://plutophotos.com/blog/best-self-hosted-photo-management-2026/)
- PhotoStructure was added to the TrueNAS community catalog on 2026-09-30 as “a self-hosted library for all your photos and videos.” No license, storage-backend, AI, or pricing page was opened. — [TrueNAS catalog](https://apps.truenas.com/catalog/)

### Inferences

- Against the offer, Immich matches the gallery, phone agent, faces, embeddings, and OCR, and it is the product a prosumer will name first. It does not match customer-paid cold object storage, two-copy deletion, content-addressed layout, captions-as-text, or transcripts. Operators who want B2 bolt rclone on beside it and accept that Glacier is a poor mount for a live timeline.
- PhotoPrism matches “index the folders you already have and do not rename them,” plus faces and optional captions. It does not match phone backup, object storage, or transcripts. Its paid team tier plus a €499 remote setup is the nearest “vendor will configure it” offer, and it is remote, not an on-site NUC.
- Ente matches S3-compatible originals and a real cold-replica bucket in the self-host config, plus polished mobile apps. Hosted Ente is the opposite of “you pay the storage vendor”: you pay Ente. E2E encryption blocks hub-side captions, OCR indexing, and transcripts.
- Nextcloud is the only mainstream photo UI in this set with a documented S3 API for the file store. It still expects the bucket to behave like a disk. Recognize’s “audio” model classifies music genre; it does not transcribe.
- LibrePhotos, PiGallery2, Photoview, Lychee, and Piwigo are folder or upload galleries. A photographer comparing archives would drop them once cold storage, verified deletion, or transcripts came up. PiGallery2 and Photoview stay relevant only as “point a web UI at a directory on a small box.”

### Gaps

- Immich AGPL was not re-read from the LICENSE file in this pass.
- No official Immich statement was found that says “S3 will not be supported.” Absence is from the storage docs, not a denial page.
- Ente’s current dollar table was not fetched from ente.com itself; two aggregators agree with each other and cite 2026-10-15.
- PhotoPrism Essentials/Plus billing period (€/month vs billed annually) is inconsistent across the editions snippet and later writeups.
- LibrePhotos iOS: docs and the monorepo README disagree.
- Lychee €5/mo and the MIT claim were not checked on Lychee’s own site.
- Piwigo and PhotoStructure feature and license pages were not opened.
- Whether any of these apps can set an S3 storage class of `GLACIER` or `DEEP_ARCHIVE` and still browse was not tested. Nextcloud exposes a storage-class field; retrieval behavior is undocumented in the pages read.
- Speech-to-text and video transcripts: not found for Immich, PhotoPrism, Ente, LibrePhotos, or Nextcloud Recognize. Absence is “not on the pages opened,” not a proof that no plugin exists.
- No product page described content-addressed dedup that preserves the original folder path only as metadata.

## Commercial "we install a box and you own the files"

### Takeaway

The commercial objects a photographer already understands are a Synology or TrueNAS they buy and keep, plus Mylio if they want a vendor-supported local-first library. None of the pages found are a seller who shows up, leaves a NUC, and leaves the customer’s Glacier bill as the only recurring fee. PhotoPrism’s remote setup fee is the closest paid onboarding, and it does not include hardware or cold storage. Client-delivery galleries (Pixieset, ShootProof, and the like) were not researched; they are a different job from an archive and should not be scored on cold storage or dedup.

### Cited Findings

- Synology’s own cloud, not customer Glacier: from 2026-06-22, C2 Storage and C2 Object Storage fold into C2 OneStorage, one pool shared across those services. Reference prices in the Synology KB: 300 GB at 29.99 USD/EUR per year; 1–200 TB at 7.99 USD/EUR per TB per month or 79.99 per TB per year. The KB says those figures are reference-only and to confirm on the C2 site. Existing subscribers can keep legacy renewal pricing through a transition that runs to 2026-12-22. — [Synology KB, C2 Storage plan change](https://kb.synology.com/C2/tutorial/Plan_Change_2026_C2_Storage)
- TrueNAS documents one-click community Immich and stable PhotoPrism, plus community Photoview, PiGallery2, Piwigo, and (added 2026-09-30) PhotoStructure. TrueNAS hosts the catalog and says the community train is not validated by TrueNAS. The disks are the operator’s. This is “you own a server and install a photo app,” not a managed on-site hub and not Glacier. — [Immich deployment](https://apps.truenas.com/resources/deploy-immich/); [Catalog](https://apps.truenas.com/catalog/)
- Mylio’s support page (updated 2026-09-25) prices Mylio Photos+ at $25/month or $240/year for an individual personal plan, and $40/month or $480/year for a single-user commercial Pro plan. It is cloud-independent. Device and attached-drive storage is the free app’s store. Mylio Drive includes unlimited encrypted optimized images. Mylio Drive+ SecureCloud, their cloud for originals, “starts at $11.98/month for 2TB,” with more in 5 TB steps at $29.95/month. A later summary that cites mylio.com says the library can keep the existing folder structure and organize by date, person, and location. That is not customer S3, not a seller-installed NUC, and not a self-hosted web gallery on a hub. — [Mylio pricing FAQ](https://support.mylio.com/how-much-does-mylio-photos-cost); [Mylio FAQ](https://support.mylio.com/faq/); [Laptop listing citing mylio.com](https://laptops251.com/programs/mylio-photos/)
- PhotoPrism sells configuration labor, not a box: remote setup €499, onboarding €179/hour, data stays on the customer’s originals folder. — [Team editions](https://www.photoprism.app/kb/teams/)
- A photographer’s published stack (2026-10-19) is the pattern people actually assemble: Synology DS220+ RAID, Immich reading an external folder, phone sync via Syncthing, off-site copy via rclone to Backblaze B2. The author treats B2 as backup of the NAS, not as the gallery’s store, and tells readers to enable backup before import. Their dollar figures ($5/month, $1.50/month) are that person’s bill, not a vendor price. — [DEV Community](https://dev.to/scsoi/my-local-first-photo-workflow-immich-syncthing-rclone-375n)
- No primary page in this pass advertised an Immich or PhotoPrism installer who leaves a NUC and whose only storage charge is the customer’s Glacier, B2, Wasabi, R2, or IDrive e2 account.

### Inferences

- Synology and TrueNAS win the “box in the closet, I own the disks” comparison. They lose the offer’s cost model: the expensive copy is spinning disks on site, and cold object storage is an extra backup product (C2, or rclone/Hyper Backup — the latter was not opened). They also do not implement the two-copy deletion rule; Immich on TrueNAS still frees phone space after a single server upload.
- Mylio is the photographer-shaped commercial library: local originals, optional vendor cloud, people and places, real money. It is a subscription app across the user’s own computers, not an on-site hub with a web AI stack.
- PhotoPrism Plus/Team is a license and support contract on software the customer hosts. It is the wrong shape for “we install the computer.”

### Gaps

- Synology Photos (faces, mobile apps, where originals sit on the volume) and Hyper Backup’s Glacier target were not opened. Do not score Synology’s AI or Glacier support from this note.
- TrueNAS Cloud Sync / B2 was not opened.
- No catalog of Immich “done for you” installers was found. Absence of a named MSP is not proof none exist.
- Mylio face recognition and any OCR or transcription were not confirmed on a feature page; the FAQ pages used here are pricing and storage.
- Pixieset, ShootProof, SmugMug, and PhotoShelter were not fetched. Leave them out of the archive comparison except as client-delivery galleries.

## Cheap cold-storage archive tools that are not a live photo app

### Takeaway

Arq and rclone are how a photographer already puts RAWs onto S3, B2, Wasabi, or a cold class without buying a gallery. They stop at bytes: no timeline, no faces, no OCR, no captions, no transcripts, and no phone catalog. Arq adds block dedup and a rule that the customer brings the bucket, which is the storage-ownership half of the offer and none of the hub or AI half. Official Arq list prices conflicted on the day this was fetched.

### Cited Findings

- Arq’s marketing page: backups go to the customer’s cloud account, NAS, or SFTP; “App only — no cloud storage included” is the positioning of the non-Premium product; features named on that page include compression, de-duplication, and block-level incremental backup. Destinations named across the current docs include Amazon S3, Backblaze B2, Google Cloud (including Coldline on the older comparison chart), Wasabi, MinIO, SFTP, and NAS. There is no gallery, face index, OCR, or transcript. — [Arq product page](https://www.arqbackup.com/arqbackup/); [Arq 7 vs Premium](https://www.arqbackup.com/documentation/arq7/English.lproj/arq7ArqPremium.html); [Destination strategy (older, still on the doc site)](https://www.arqbackup.com/documentation/pages/strategy.html)
- Price conflict on 2026-10-24, all on Arq properties. Checkout: Arq 7 is $59.99 per computer, one-time, 12 months of updates, app only; Arq Premium is $6.99/month or $69.99/year for up to 5 computers and 1 TB, then $.00699 per extra GB-month, plus web access to the backup. The public pricing URL instead shows Arq 7 at $49.99 and Premium at $59.99/year with extra storage at $.00599/GB per month. Do not pick one. Premium’s included terabyte is Arq’s cloud, which breaks “customer pays the storage vendor” for that SKU only. — [Purchase](https://cloud.arqbackup.com/purchase); [Pricing](https://www.arqbackup.com/pricing/); [Premium checkout](https://cloud.arqbackup.com/purchase/arqpremium)
- rclone is the tool a photography-backup guide (2026-01-17) recommends for RAW folders and Lightroom catalogs to S3-compatible storage, excluding preview files. ### Inferences

- Arq is the commercial “you own the bucket” product a careful photographer already pays for. It overlaps the offer on storage ownership, client-side encryption, and block dedup. It does not install a hub, does not publish a web photo catalog, and does not run faces, OCR, captions, or transcripts. Premium web access is file restore, not a library.
- rclone (and lifecycle rules into Deep Archive) is the DIY version of the cold leg. Pairing it with Immich, as in the Synology writeup, is the common compromise: live app on hot disk, cold copy as an invisible backup. The offer’s difference is that the cold copy is part of the deletion rule and the gallery, not a second product the user has to remember.
- Lightroom’s cloud is the incumbent subscription archive. It fails storage ownership even when the desktop catalog stays local. Pricing must come from Adobe, not from an S3 reseller’s comparison table.
