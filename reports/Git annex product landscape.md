# Nobody sells a git-annex photo product

As of 2026-10-24, **no company, consultant, appliance, or managed archive was found whose product is git-annex**, and **no commercial or open-source photo or video product was found that stores its library in git-annex**. Upstream does not ship a UI like the hub gallery under comparison. Its three interfaces are the command line, the assistant daemon, and a localhost webapp that sets up repositories and watches transfers. That webapp does not browse images, build a thumbnail grid, or run captions, OCR, embeddings, face detection, or transcription. The maintained ecosystem around the tool is scientific data software — DataLad, GIN, OpenNeuro, and DANDI’s DataLad mirror — plus a Forgejo soft-fork and small desktop utilities, not a consumer archive. Photographers who want a live library instead self-host Immich, PhotoPrism, or Ente, buy a Synology or TrueNAS and install a photo app, or push bytes with Arq or rclone. **None of the official pages opened for those substitutes mention git-annex.** The comparison bar — an open-source on-site hub, customer-paid object storage, deletion of the source only after a hub copy and a cold copy both exist, content-addressed files with the source path kept as metadata, and an on-hub gallery that also captions, OCRs, embeds, detects faces, and transcribes — is not a product anyone in these notes is selling. Image Annex itself was not a public GitHub listing on the research date (the unauthenticated API returned HTTP 404) and is excluded from the competitor set ([GitHub API](https://api.github.com/repos/InTEGr8or/image-annex)).

## No company is selling git-annex

git-annex is free software, written in Haskell, with **no pricing page, SKU, or support contract** on its own site. The project is alive — recent news lists **version 10.20261020** — but it is not a vendor ([git-annex](https://git-annex.branchable.com/); [version 10.20260717](https://git-annex.branchable.com/news/version_10.20260717/)). Its related-software page, crawled 2026-07-02, lists free software, academic platforms, and cultural projects, and **does not list a company, appliance, NAS image, or paid support offering** ([related software](https://git-annex.branchable.com/related_software/)). The testimonials page is old user quotes from 2012–2013 plus the author’s personal use, not customers of a git-annex company ([testimonials](https://git-annex.branchable.com/testimonials/)). DataLad, the main layer people build on git-annex, calls itself free and open source, points users at Matrix, office hours, and GitHub, and credits NSF, BMBF, NIH/ReproNim, EU Horizon 2020, and DFG grants. **No paid plan is listed** ([datalad.org](https://datalad.org/)).

Built-in special remotes already speak **S3, Amazon Glacier, WebDAV, rclone, rsync, borg, bup, and a directory**. Those are protocols for storage the user already owns. They are not a hosting product ([special remotes](https://git-annex.branchable.com/special_remotes/)). GIN, the G-Node neuroscience repository, will talk to someone whose data needs fall outside the standard service, at info@g-node.org. That line is academic help, not a price list ([GIN about](https://gin.g-node.org/G-Node/Info/wiki/about)). Searches on 2026-10-24 for a commercial product, consulting practice, managed service, appliance, or startup returned the project site, an aggregator that invents a “free plan” for the free tool, AlternativeTo, and ordinary Git consultancies that never mention git-annex ([EZToolset](https://eztoolset.com/tools/git-annex/); [MeteorOps](https://meteorops.com/technologies/git/); [IDEA GitLab](https://gitlab.consulting/en-gb/)). Names that sound like a vendor — Annex.com, Annexus Technology, Anavon, Blunix — are records software or generic Linux hosts, not git-annex ([Directus case study](https://directus.io/built-with-directus/annex-organizational-bliss); [Annexus](https://www.annexustech.ca/support-services)). Forum archives were not crawled for a one-off “I will install this” post, and a private invoice would not have shown up. Nothing public amounts to a product category comparable to a paid Immich host or a Synology package. People who want git-annex buy ordinary disks or an S3-compatible bucket and run the free tool.

## Upstream’s own UI never became a gallery

**Upstream ships three interfaces, and none of them is a photo or video gallery.** The command line is the real product: `git annex assistant` is a daemon that watches a tree, adds files, and downloads what other remotes publish. It is not a screen ([git-annex-assistant](https://git-annex.branchable.com/git-annex-assistant/)). Placement is an expression, `preferred content`, edited with `git annex vicfg` or `git annex wanted`, with stock groups such as client, transfer, backup, archive, and source ([git-annex-preferred-content](https://git-annex.branchable.com/git-annex-preferred-content/); [forum on vicfg](https://git-annex.branchable.com/forum/Reappearing_repos_in_webapp_and_vicfg/)). The assistant, Kickstarter-funded and still inside git-annex rather than a separate app, keeps a synchronized folder across Linux, macOS, Android-via-Termux, removable drives, NAS boxes, and cloud services ([assistant](https://git-annex.branchable.com/assistant/)). The third interface, `git annex webapp`, opens a local browser on a setup-and-control panel. Default access is localhost, URLs carry an `auth=` token, and optional PEM files turn on HTTPS ([git-annex-webapp](https://git-annex.branchable.com/git-annex-webapp/)). The screens that the design log marks done are transfer progress, pause, repository groups, preferred content, and wizards for a new repo, a USB clone, SSH, Amazon S3, encrypted rsync, Rsync.net, pairing, and an Internet Archive publisher. A file-export UI that would serve a file over HTTP is written as something that could exist, not as a feature ([design/assistant/webapp](https://git-annex.branchable.com/design/assistant/webapp/); [configurators](https://git-annex.branchable.com/design/assistant/configurators/); [day 248](https://git-annex.branchable.com/design/assistant/blog/day_248__Internet_Archive/)).

**The webapp is still shipped and is not formally deprecated, and Joey Hess has an open todo proposing to delete it.** The man page was last edited 2024-01-25 and still describes the same app. Termux instructions still tell the user to run `git-annex webapp`. News through **10.20261020** does not announce a removal. The `removewebapp` branch is described as a working patch that is not presented as merged; the assistant would stay; reasons given include about ten years of minimal maintenance, no new features, no way to configure exporttree special remotes, and **28 thousand lines** including embedded Bootstrap and jQuery ([todo/remove webapp](https://git-annex.branchable.com/todo/remove_webapp/); [news](https://git-annex.branchable.com/news/); [install/termux](https://git-annex.branchable.com/install/termux/)). v10 did not replace that 2012–2014 dashboard with a gallery.

git-annex also does not generate thumbnails or search pixels. It stores arbitrary per-key metadata and can check out **metadata views** as directories (`git annex view tag=*`), which a normal file manager then browses. A user with about **7,050** photo files reported a year/address view taking about **377 seconds**, which is a git checkout, not a lazy thumbnail index ([metadata](https://git-annex.branchable.com/metadata/); [views](https://git-annex.branchable.com/tips/metadata_driven_views/); [view performance](https://git-annex.branchable.com/forum/View_performance_with_7%2C000_files/)). EXIF and ID3 extraction is a sample `pre-commit-annex` hook that shells out to GNU `extract` or `exiftool` if the user installs them. The tip was last edited in 2016. Year and month from `annex.genmetadata` are described as when that version of the file came into being, not as EXIF ([automatically adding metadata](https://git-annex.branchable.com/tips/automatically_adding_metadata/)). The command list updated 2026-10-20 is `metadata`, `view`, `vpop`, `vfilter`, `vadd`, and `vcycle`. **No thumbnail, OCR, embedding, face, or transcription command appears** ([git-annex](https://git-annex.branchable.com/git-annex/)). Third-party metadata UIs are not galleries either. git-annex-metadata-gui (last push 2017-08-23) edits fields and can preview one image or text file ([GitHub](https://github.com/alpernebbi/git-annex-metadata-gui)). DataLad Gooey’s Metadata tab queries and writes fields ([DataLad Gooey](https://docs.datalad.org/projects/gooey/en/latest/annexmetadata.html)). git-annex-browser, pushed 2026-10-04, is a view-only terminal list of keys, locations, and sizes ([git-annex-browser](https://github.com/janttsu/git-annex-browser)). git-annex-turtle badges presence in macOS Finder ([git-annex-turtle](https://github.com/andrewringler/git-annex-turtle)). Search is `git annex find` over field strings and mime types.

There is **no current official app on F-Droid or the Play Store, and no official iOS app**. The supported phone path is the Linux build inside Termux (`pkg install git-annex`) or Nix-on-Droid, which runs the same assistant and the same webapp. A computer can also sync a phone with the `adb` special remote without installing git-annex on the device ([Android](https://git-annex.branchable.com/Android/); [adb tip](https://sources.debian.org/src/git-annex/10.20251029-1/doc/tips/android_sync_with_adb.mdwn)). The old Android APK is deprecated and frozen on Android 4.0–5.0, last edited as a page on 2019-01-21, and what it opened was a terminal plus the same webapp ([oldapp](https://git-annex.branchable.com/install/Android/oldapp/)). Its one photo-specific idea, a camera folder in the `source` preferred-content group so the phone “will only hang onto photos and videos until they’re uploaded,” is a one-hop upload rule from 2013, not a verified second cold copy and not a catalog ([day 254](https://git-annex.branchable.com/design/assistant/blog/day_254__Android_app_polishing/)). A phone browser pointed at the webapp is a sync-admin page. No third-party Android or iOS client with a git-annex backend turned up in the install pages, the related-software list, or a 2026 web search ([related software](https://git-annex.branchable.com/related_software/)). F-Droid was not opened by package id, and a GitHub name search hit HTTP 403, so a tiny unpublished client is a gap rather than a disproof. Upstream’s documented phone experience in 2026 is a Linux terminal.

## The live git-annex deployments are scientific, not photographic

**The maintained applications are data tools.** DataLad, pushed on GitHub on 2026-10-21 (669 stars at query time), versions large files as datasets on top of Git and git-annex, with clone, get, drop, and push. Its handbook still documents adjusted mode, annex encryption, and `annex.largefiles`. The homepage mentions a GUI. That GUI is not a media gallery ([datalad.org](https://datalad.org/); [datalad/datalad](https://github.com/datalad/datalad)). GIN is a free web repository for neuroscience data on Git, git-annex, and Gogs, with a web UI, a local client, and WinGIN, and it documents self-hosting ([GIN](https://gin.g-node.org/)). OpenNeuro’s docs, updated 2026-10-21, say a dataset’s underlying format is a git-annex repo created with DataLad, with public file content on a preconfigured S3 special remote ([OpenNeuro git access](https://docs.openneuro.org/git)). DANDI’s docs, updated 2026-09-17, mirror dandisets as DataLad datasets and encode the version-to-S3 mapping inside git-annex. The GitHub org readme describes access to on the order of a petabyte of neural data whose blobs live in DANDI’s own S3 archive ([DANDI downloading](https://docs.dandiarchive.org/user-guide-using/accessing-data/downloading/); [dandisets](https://github.com/dandisets)). Forgejo-aneksajo is a maintained 2026 soft-fork of the Forgejo git forge with git-annex integration. CI showed `v14.0.3-git-annex2` activity on 2026-03-16. It is a forge, not a gallery, and it is not sold ([wiki](https://codeberg.org/forgejo-aneksajo/forgejo-aneksajo/wiki); [actions](https://codeberg.org/forgejo-aneksajo/forgejo-aneksajo/actions)).

Cultural and personal uses exist and still are not products. Upstream says Densho moves “upwards of 10+ terabytes” of cultural-heritage material on USB drives and has a Django web UI. That is an institution’s internal tool. The Django app was not re-checked, so current use is the related-software blurb, not a fresh audit ([related software](https://git-annex.branchable.com/related_software/)). Isuma’s media players are quoted as a two-way distribution network for communities with poor connections. No 2026 commit or company status was fetched. Baobáxia, a Brazilian community sync project, last pushed in 2020. The darktable bridge last pushed on 2021-08-19 and does not replace darktable’s storage ([darktable-git-annex](https://github.com/xxv/darktable-git-annex)). Personal blogs — one dated 2026-08-14 that explicitly is not the assistant, and one from 2024-03-13 about moving a family blog off GitLab — are workflows ([aaron.na31.org](https://aaron.na31.org/git-annex_photography); [switowski.com](https://switowski.com/blog/git-annex/)). A 2024 Reddit post with a score of 3 plans to point git-annex at an Immich library and copy it to S3 or Glacier. Immich stays the photo app ([Reddit](https://www.reddit.com/r/immich/comments/1fvr9vf/using_immich_with_git_annex_for_backup/)). The official related-software list has **no gallery, DAM, Immich-like app, Lightroom-like app, or NAS photo app**, and no Nautilus or Dolphin product. GitHub code search was not finished because of a 403, so an oddly named private gallery is an unclosed gap. The maintainer’s own list, as crawled in July 2026, does not name one.

## Immich, PhotoPrism, and Ente cover the gallery and skip the annex

The products a photographer would open next to this offer are **Immich first, then PhotoPrism or Ente**. None of their official pages in this pass mention git-annex. That is not a full-site audit. None of them document content-addressed blob storage that keeps the folder path only as metadata, and none document deleting a source only after both a hub copy and a verified cold-object copy exist.

Immich is the live-app substitute. Storage in the official install docs is a Unix filesystem bind mount (`UPLOAD_LOCATION`). Postgres “should ideally use local SSD storage, and never a network share.” **There is no S3, B2, R2, or Glacier library backend on those pages** ([custom locations](https://docs.immich.app/guides/custom-locations/); [requirements](https://docs.immich.app/install/requirements)). External libraries are directories on the same machine ([external library](https://github.com/immich-app/immich/blob/main/docs/docs/guides/external-library.md)). A three-star community compose file mounts S3 or WebDAV with rclone and then scans that path. That is FUSE, not an Immich driver ([toby1991/immich-s3](https://github.com/toby1991/immich-s3)). On 2026-10-19 Backblaze Labs published an “Immich B2 Backend” that stores originals, thumbnails, and CLIP embeddings on B2, labeled **unsupported, with no SLA**, and explicitly out of scope for face recognition and video transcoding. It is not the Immich server ([Backblaze Labs](https://www.backblaze.com/labs/projects/immich-object-storage-backend/)). Phone backup on iOS, Android, and the web checksums content and skips bytes already on the server ([mobile backup](https://docs.immich.app/features/mobile-backup)). “Free Up Space,” shipped around v2.5 in January 2026, removes device files only after Immich considers them backed up to **the server**, not to a second off-site copy, and database dumps do not contain the photos ([mobile app](https://docs.immich.app/features/mobile-app); [backup and restore](https://github.com/immich-app/immich/blob/main/docs/docs/administration/backup-and-restore.md)). Dedup is an upload checksum plus a visual-similarity utility, and storage templates write paths such as `Year/Year-Month-Day/Filename.Extension` ([duplicates](https://docs.immich.app/features/duplicates-utility); [storage template](https://docs.immich.app/administration/storage-template)). On the server, CLIP search defaults to `ViT-B-32__openai` and, per the FAQ, does not produce readable captions. Faces default to `buffalo_l`. OCR search (“Text in images”) defaults on with `PP-OCRv5_mobile`. A secondary report dated 2026-10-11 says 3.3 added PP-OCRv6 model sizes. The config example still names v5, so v6 is an added family, not a confirmed new default. Face detection on video uses the thumbnail only. **No speech or video transcription** appears on the searching, FAQ, or architecture pages opened ([searching](https://docs.immich.app/features/searching/); [FAQ](https://docs.immich.app/FAQ); [config](https://docs.immich.app/install/config-file)). Secondary roundups call the license AGPL-3.0. This pass did not open the LICENSE file ([SelfHostLab](https://selfhostlab.io/apps/immich/)).

PhotoPrism indexes a folder in place. Originals stay at `PHOTOPRISM_ORIGINALS_PATH`. Indexing leaves names and folders unchanged. Import can move into originals and then delete the source, which is one local copy, not a verified cloud replica. Duplicate detection compares SHA1 and size. The web UI for browsing duplicates is “planned for a future release.” **No S3 or Glacier library** appears in the originals, folders, or WebDAV docs opened here ([originals](https://docs.photoprism.app/user-guide/library/originals/); [duplicates](https://docs.photoprism.app/user-guide/library/duplicates/)). The mobile row on every edition, including the free Community Edition, is “PWA & PhotoSync,” not a first-party backup app ([editions](https://www.photoprism.app/editions)). Faces use YuNet and SFace. Captions and richer labels are optional through self-hosted Ollama or the OpenAI API. PhotoPrism’s Ollama notes attribute “32-language OCR” to the Qwen3-VL model. That is model capability, not a documented library-wide OCR index. No transcript feature was on the AI pages opened ([AI](https://docs.photoprism.app/user-guide/ai/); [Ollama README](https://github.com/photoprism/photoprism/blob/develop/internal/ai/vision/ollama/README.md)). The editions page prices Community at FREE, Essentials at **€2.00/month**, Plus from **€6.00/month**, managed PikaPods from **$6.50/month**, team Starter at **€79.00/month**, Business from **€219.00/month**, and Enterprise from **€1499.00/month**. Remote setup is **€499.00**, and onboarding is **€179.00/hour** ([editions](https://www.photoprism.app/editions); [teams](https://www.photoprism.app/kb/teams/)). Aggregators disagree with that page and with each other on whether Essentials is monthly or annual. Use the editions page, and treat the billing period as unsettled until checkout.

Ente is the substitute that actually stores originals as S3 objects. Hosted Ente is end-to-end encrypted. Clients upload ciphertext, Ente says it cannot read the photos, and replicas sit on Ente’s providers. TechCrunch in April 2025 said three locations. **The customer does not point hosted Ente at their own Glacier account** ([TechCrunch](https://techcrunch.com/2025/04/01/ente-wants-to-take-on-google-photos-with-its-privacy-first-photo-storage-service/); [storage FAQ](https://ente.com/help/photos/faq/storage-and-plans)). The official FAQ says the free plan is **10 GB**, paid tiers run from **50 GB to multiple terabytes**, family sharing covers up to five people, and there is one global price. Dollar amounts were not fetched from ente.com in this pass. A secondary page that says it copied ente.com on 2026-10-15 lists Starter at $2.49/month (50 GB) through Pro+ at $19.99/month (2000 GB). TechCrunch’s April 2025 “from $9.99/month for 1 TB” is an older, higher entry tier ([storage FAQ](https://ente.com/help/photos/faq/storage-and-plans); [Position Is Everything](https://www.positioniseverything.net/tools/ente-photos/pricing/)). Self-hosted Museum uses the same code as production, with files as S3 objects. Default bucket keys in `museum.yaml` are named `b2-eu-cen` (primary), `wasabi-eu-central-2-v3` (secondary), and `scw-eu-fr-v3`, documented as cold storage. External S3 is supported by setting `s3.are_local_buckets` to false. **The docs do not say those buckets can be Glacier or Deep Archive, and they do not describe deleting a camera card after two copies** ([object storage](https://ente.io/help/self-hosting/administration/object-storage)). Apps exist for Android, iOS, desktop, and web. Machine learning is on-device and off by default: face clustering and CLIP search, unavailable on web.ente.io. Detect Text is an on-demand viewer action on iOS and Android photos, explicitly not a searchable index and not for video. Because the server holds ciphertext, server-side captions or transcripts do not fit the hosted design unless they also run on the client ([machine learning](https://ente.io/help/photos/features/search-and-discovery/machine-learning); [Detect Text](https://ente.com/help/photos/features/utilities/detect-text)).

Smaller galleries are folder or upload sites. LibrePhotos scans folders the user already has, runs InsightFace, and generates captions. Its mobile docs, dated 2026-02-23, still call the official app an Android proof of concept, while the monorepo README, pushed 2026-10-24, describes an Expo app for Android and iOS. Those pages conflict, so a shipping iOS app is not confirmed. No S3 or verified-deletion language is on the docs homepage or README ([LibrePhotos docs](https://docs.librephotos.com/); [mobile guide](https://docs.librephotos.com/docs/user-guide/mobile/librephotos-mobile/); [GitHub](https://github.com/LibrePhotos/librephotos)). Nextcloud can put files on Amazon S3 or any S3-compatible store, including an optional storage class, and Memories is the timeline UI, with faces delegated to Recognize. Recognize’s audio model tags music genre with an Audio Spectrogram Transformer. **That is not speech-to-text**, and the S3 pages do not discuss Glacier retrieval, so a live Memories library on Glacier is not an official configuration ([S3 external storage](https://docs.nextcloud.com/server/latest/admin_manual/configuration_files/external_storage/amazons3.html); [Recognize](https://docs.nextcloud.com/server/stable/admin_manual/ai/app_recognize.html)). PiGallery2, updated 2026-10-18, is a directory grid with on-demand thumbnails, metadata, and video transcode, without a documented face detector, OCR index, captions, or transcripts ([features](https://bpatrik.github.io/pigallery2/features/)). Photoview scans a filesystem. Its homepage, updated 2025-10-16, says the official iOS app is no longer on the App Store ([Photoview](https://photoview.github.io/)). Lychee and Piwigo show up in 2026 roundups as publish-and-share galleries. Lychee’s reported €5/month price was not confirmed on an official page, and Piwigo’s license, S3, and AI pages were not opened, so those claims stay out. Speech-to-text was not found on the Immich, PhotoPrism, Ente, LibrePhotos, or Recognize pages that were opened. That is absence from those pages, not a proof that no plugin exists.

## NAS boxes and backup tools each hold half the offer

**No page in this pass advertised a seller who leaves a small on-site computer and whose only recurring storage charge is the customer’s Glacier, B2, Wasabi, R2, or IDrive e2 account.** The commercial objects a photographer already understands are a Synology or TrueNAS they buy and keep, plus Mylio if they want a vendor-supported library on their own devices. Synology’s cloud is Synology’s cloud. From 2026-06-22, C2 Storage and C2 Object Storage fold into C2 OneStorage. The KB’s reference prices are **300 GB at 29.99 USD or EUR per year**, and **1–200 TB at 7.99 USD or EUR per TB per month or 79.99 per TB per year**, flagged as reference-only. Those are not a customer Glacier bill ([Synology KB](https://kb.synology.com/C2/tutorial/Plan_Change_2026_C2_Storage)). Synology Photos and Hyper Backup’s Glacier target were not opened, so Synology’s face detection and Glacier behavior are not scored here. TrueNAS documents one-click community Immich and stable PhotoPrism, plus community Photoview, PiGallery2, Piwigo, and, added 2026-09-30, PhotoStructure. TrueNAS says the community train is not validated by TrueNAS. The disks are the operator’s. This is “you own a server and install a photo app,” not a managed hub and not Glacier ([catalog](https://apps.truenas.com/catalog/); [Immich on TrueNAS](https://apps.truenas.com/resources/deploy-immich/)). PhotoStructure’s license, storage backend, and AI pages were not opened.

Mylio’s support page, updated 2026-09-25, prices Photos+ at **$25/month or $240/year** for an individual personal plan and **$40/month or $480/year** for a single-user commercial Pro plan. Device and attached-drive storage is the free app’s store. Mylio Drive+ SecureCloud, their cloud for originals, “starts at **$11.98/month for 2 TB**,” then 5 TB steps at $29.95/month. A later summary that cites mylio.com says the library can keep the existing folder structure. That is not customer S3, not a seller-installed hub, and not a self-hosted web gallery. Face recognition, OCR, and transcription were not confirmed on a Mylio feature page in this pass ([pricing FAQ](https://support.mylio.com/how-much-does-mylio-photos-cost); [FAQ](https://support.mylio.com/faq/)). PhotoPrism’s **€499** remote setup is the closest paid onboarding, and it does not include hardware or cold storage ([teams](https://www.photoprism.app/kb/teams/)). The pattern people actually publish, in a 2026-10-19 writeup, is a Synology DS220+, Immich reading a folder, Syncthing from the phone, and rclone to Backblaze B2 as a backup of the NAS. The author’s dollar figures are that person’s bill, not a vendor price ([DEV Community](https://dev.to/scsoi/my-local-first-photo-workflow-immich-syncthing-rclone-375n)). Client-delivery galleries such as Pixieset and ShootProof were not researched. They are a different job and should not be scored on cold storage.

Arq and rclone are how a photographer already puts files on object storage without buying a gallery. **They stop at bytes.** Arq’s marketing page sends backups to the customer’s cloud account, NAS, or SFTP, and the non-Premium product is “app only — no cloud storage included,” with compression, de-duplication, and block-level incremental backup. Destinations named in current docs include Amazon S3, Backblaze B2, Wasabi, MinIO, SFTP, and NAS. There is no gallery, face index, OCR, or transcript ([Arq](https://www.arqbackup.com/arqbackup/); [Arq 7 vs Premium](https://www.arqbackup.com/documentation/arq7/English.lproj/arq7ArqPremium.html)). Official list prices conflicted on the day they were fetched. Checkout showed Arq 7 at **$59.99** per computer, one-time, and Arq Premium at **$6.99/month or $69.99/year** for up to five computers and 1 TB, then $.00699 per extra GB-month. The public pricing URL showed Arq 7 at **$49.99** and Premium at **$59.99/year** with extra storage at $.00599/GB per month. Do not pick one. Premium’s included terabyte is Arq’s cloud, which breaks “the customer pays the storage vendor” for that SKU only ([purchase](https://cloud.arqbackup.com/purchase); [pricing](https://www.arqbackup.com/pricing/)). rclone is what a 2026 photography-backup guide recommends for RAW folders to S3-compatible storage. That guide is a storage vendor’s blog, so its Adobe and per-terabyte prices are not used. A 2023 rclone-forum thread describes Glacier as awkward: no cheap server-side compare, so people are afraid to delete the local copy. **rclone does not productize a “delete only after both copies exist” rule** ([DanubeData](https://danubedata.ro/blog/photography-backup-raw-files-s3-storage-guide-2025); [rclone forum](https://forum.rclone.org/t/rclone-wrapper-for-data-archiving-to-glacier-etc/37752)). A 2026-05-01 homelab note uses rclone `copy` plus a lifecycle rule into Glacier Deep Archive: a sync and a bucket policy, with no gallery ([Zenn](https://zenn.dev/yostos/articles/rclone-s3-cold-archive)). Duplicacy and restic were not opened, so they are not scored. Adobe’s current Photography-plan quota was not opened on adobe.com. Lightroom’s cloud, as described only by that reseller guide, is subscription storage Adobe hosts, not customer Glacier and not a self-hosted gallery.

## Conclusion

The market already split this job into pieces that refuse to meet. git-annex already content-addresses files, already talks to S3 and Glacier, and already lets a `source` repository drop files after they are wanted elsewhere, and nobody wrapped that into a gallery, a phone catalog, or a paid on-site install. The scientific hosts prove the storage layer can sit under a real web service at petabyte scale, and they prove the users of that pattern are archives of research data, not photographers. Immich is what a prosumer will name when the conversation is faces, CLIP search, OCR, and a phone that frees its own space. Ente is what they will name when the conversation is an S3 bucket and a cold replica. Arq is what they will name when the conversation is “I own the bucket.” Each of those answers drops the other half, and pairing Immich with rclone, which is the published homelab compromise, keeps the cold copy invisible to the gallery and outside the deletion rule. The open seat is not another timeline. It is a single system in which the cold object the customer pays for is part of how a file is allowed to leave the camera card, and in which the hub that enforces that rule is also the place that captions, reads, embeds, and transcribes the file.
